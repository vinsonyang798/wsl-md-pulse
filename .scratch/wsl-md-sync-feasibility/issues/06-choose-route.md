# 选定路线（go / no-go 与拓扑）

## Question

对照"使用场景与'同步显示'的验收标准"，在剩余候选中作出决定，写明取舍理由与已知风险：

- **A. 以现成工具为基线**：主要候选是 Vantage。原样使用（接受没有跟随模式、按像素恢复位置），或者把缺口做成补丁提给上游或 fork 维护。依据"现成工具对照验收标准的差距"。
- **B. 自己做**：WSL 内单文件静态二进制服务 + Windows 浏览器经 localhost 访问（约束见"Windows 侧访问 WSL 内服务与画面通道"）。
- **E. no-go**：真机实测表明无法达到验收标准。

已排除（依据"使用场景与'同步显示'的验收标准"）：VS Code 内置预览（用户实测不自动刷新）；编辑器扩展（要求独立预览页）；Windows 侧程序读 `\\wsl.localhost`（Windows 不装任何东西，且该路径收不到变更通知）。

真机实测（第 3 批）确认 Vantage 有三个缺口：阅读位置按像素恢复（插入一节后偏了一节）；刷新时白屏；没有跟随模式。另有一个待定口径："写入完成后 ≤ 1 秒"在持续写入期间按最后一次写入算，还是按每一次写入算。按每一次写入算，Vantage 1 秒的最长等待不达标。

若选 A 或 B，还要确定变化感知方式（ext4 上 inotify 监听目录 + 防抖；是否需要轮询兜底，例如 `ENOSPC` 时）。

## Answer

**go。路线 A：原样使用 Vantage v0.7.1，外面包一层 `mdv` 启动命令。仓库原有的自研设计（Go + React 的 wsl-md-pulse）保留为备选，暂不实施。** 过程见下方 5 轮讨论。

- **拓扑**：Vantage 跑在 WSL 内，绑 `127.0.0.1`，用 fsnotify 递归监听 ext4 上的目录；Windows 浏览器通过 `http://127.0.0.1:<端口>/` 访问。真机已验证。
- **用法**：在 WSL 终端里进入要看的目录，运行 `mdv`（或 `mdv <目录>`），用法类似 `code .`：
  - 在后台启动 `vantage serve <目录> --no-open`，不指定端口，从 8000 起自动往后找空闲端口；
  - 从 Vantage 的输出里读出实际地址，用 `cmd.exe /c start` 打开 Windows 浏览器（真机已验证），失败则依次改用 `powershell.exe`、打印 URL；
  - 然后把提示符还给用户。
  - 每个目录一个实例，同时开多个目录时端口自动错开；在同一个目录再运行一次，只重新打开浏览器，不重复启动。
  - 关闭启动它的终端标签页后，该实例随之停止。
  - 只支持 ext4，目录在 `/mnt/` 下时给出警告。
- **版本**：固定 v0.7.1，由用户手动决定何时升级；升级前用 `probe/wsl-probe.sh vantage` 回归。
- **放宽后的验收标准**（已写入"使用场景与'同步显示'的验收标准"的"后续修订"）：
  - 延迟以 Vantage 实测为准：单次写入约 0.1 秒，持续密集写入时最坏约 1.5 秒；
  - 允许刷新时短暂白屏；
  - 刷新后不跳回顶部即可，偏移约等于上方插入内容的高度；
  - 跟随模式先用侧栏的"Recent"列表手动代替；
  - 接受 Vantage 自带的非只读功能，以及其写接口没有 CSRF 校验的风险。
- **变化感知**：由 Vantage 负责。不做轮询兜底；真机的 inotify 上限是 524288。
- **回到"自己做"的触发条件**（满足任一条）：
  - Vantage 停更，或新版本出现无法接受的改动；
  - 用户想要回按标题恢复阅读位置、跟随模式、不白屏或严格只读中的任何一项。
  - 回到自研时，参考 Vantage 的监听、合并窗口、Origin 白名单和路径校验（Apache-2.0，复制代码需保留 LICENSE/NOTICE）。
- **已知风险**：
  - Vantage 项目小众（14★）、迭代快，也没有声明测试过 WSL；
  - 持续密集写入时页面最多落后约 1.5 秒；
  - 睡眠、断网后的恢复和真实目录的规模还没实测（见地图"交接"一节）。
