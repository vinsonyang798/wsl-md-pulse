# 选定路线（go / no-go 与拓扑）

## Question

对照"使用场景与'同步显示'的验收标准"，在剩余候选中作出决定，写明取舍理由与已知风险：

- **A. 以现成工具为基线**：主要候选是 Vantage。原样使用（接受没有跟随模式、按像素恢复位置），或者把缺口做成补丁提给上游或 fork 维护。依据"现成工具对照验收标准的差距"。
- **B. 自己做**：WSL 内单文件静态二进制服务 + Windows 浏览器经 localhost 访问（约束见"Windows 侧访问 WSL 内服务与画面通道"）。
- **E. no-go**：真机实测表明无法达到验收标准。

已排除（依据"使用场景与'同步显示'的验收标准"）：VS Code 内置预览（用户实测不自动刷新）；编辑器扩展（要求独立预览页）；Windows 侧程序读 `\\wsl.localhost`（Windows 不装任何东西，且该路径收不到变更通知）。

真机实测（第 3 批）确认 Vantage 有三个缺口：阅读位置按像素恢复（插入一节后偏了一节）；刷新时白屏；没有跟随模式。另有一个待定口径："写入完成后 ≤ 1 秒"在持续写入期间按最后一次写入算，还是按每一次写入算。按每一次写入算，Vantage 1 秒的最长等待不达标。

若选 A 或 B，还要确定变化感知方式（ext4 上 inotify 监听目录 + 防抖；是否需要轮询兜底，例如 `ENOSPC` 时）。
