# 选定路线（go / no-go 与拓扑）

## Question

对照"使用场景与'同步显示'的验收标准"，在剩余候选中作出决定，写明取舍理由与已知风险：

- **A. 以现成工具为基线**：主要候选是 Vantage。原样使用（接受没有跟随模式、按像素恢复位置），或者把缺口做成补丁提给上游或 fork 维护。依据"现成工具对照验收标准的差距"。
- **B. 自己做**：WSL 内单文件静态二进制服务 + Windows 浏览器经 localhost 访问（约束见"Windows 侧访问 WSL 内服务与画面通道"）。
- **E. no-go**：真机实测表明无法达到验收标准。

已排除（依据"使用场景与'同步显示'的验收标准"）：VS Code 内置预览（用户实测不自动刷新）；编辑器扩展（要求独立预览页）；Windows 侧程序读 `\\wsl.localhost`（Windows 不装任何东西，且该路径收不到变更通知）。

真机实测（第 3 批）确认 Vantage 有三个缺口：阅读位置按像素恢复（插入一节后偏了一节）；刷新时白屏；没有跟随模式。另有一个待定口径："写入完成后 ≤ 1 秒"在持续写入期间按最后一次写入算，还是按每一次写入算。按每一次写入算，Vantage 1 秒的最长等待不达标。

若选 A 或 B，还要确定变化感知方式（ext4 上 inotify 监听目录 + 防抖；是否需要轮询兜底，例如 `ENOSPC` 时）。

## Comments

### 第 1 轮（2026-09-28）

1. **持续写入期间"≤ 1 秒"的口径**：从最后一次写入算，还是从每一次写入算？建议：从最后一次写入算，同时要求持续写入期间页面最多落后约 1 秒。
2. **Vantage 的三个缺口里哪些是硬要求**：阅读位置按标题段落恢复、刷新不白屏（白屏算不算"整页跳动"）、跟随模式。建议：三个都保留为硬要求，这样"原样使用 Vantage"就排除了。
3. **"严格只读 + 最小功能面"是不是硬要求**：Vantage 带收藏、评审批注、inbox 等写入功能；写接口没有 CSRF 校验；inbox 会删除、改名笔记根目录下 `.vantage/inbox` 里的文件。建议：是硬要求。二进制里不应有能被网页触发的写入功能。
4. **go 还是 no-go**：真机验证表明拓扑可行，缺口都在应用层，没有平台层的阻碍。建议：go，排除 E。

**用户回答**：

1. 当前效果已经够用。按 Vantage 实测的延迟接受，包括持续密集写入时最坏约 1.5 秒。
2. 插入一节后从第 20 节偏到第 19 节，可以接受；刷新时白屏，可以接受。跟随模式没有回答。
3. 只要有只读预览功能就行，带其他功能无所谓。
4. 必须 go，排除 E。

**影响**：验收标准第 3 条（1 秒内刷新）和第 4 条（刷新不整页跳动、按标题段落恢复阅读位置）实际上放宽了，"原样使用 Vantage"重新成为候选。是否成立，取决于跟随模式是不是硬要求（第 2 轮）。

### 第 2 轮（2026-09-28）

5. **跟随模式是不是硬要求**：Vantage 没有自动切换，但侧栏有一个按修改时间排序的"Recent"列表，可以手动点开 agent 刚改的文档。建议：先不作为硬要求，用"Recent"列表手动代替；真用起来觉得不够，再给 Vantage 补一个小的前端补丁（改一个 hook，加一个开关，服务端不用改）。
6. **"阅读位置"这个术语要不要改**：`CONTEXT.md` 把它定义为"标题段落，按它恢复位置，而不是按像素"，这正是 Vantage 做不到的。偏移量大约等于插入内容的高度：插入一节偏一节；如果 agent 在上方插入 200 行，会偏好几节甚至一整屏以上。建议：把验收标准改为"刷新后不跳回顶部，偏移大约等于上方插入内容的高度"；"阅读位置"的定义保留，标为以后的改进项。
7. **接受 Vantage 写接口没有 CSRF 校验的风险**：在同一个 Windows 浏览器里打开一个恶意网页，就可以向 `127.0.0.1:<端口>` 发 POST，写入收藏和评审批注。这些数据写在 `~/.local/share/vantage/` 下，不会写进笔记根目录。inbox 只有在有人往 `.vantage/inbox` 里放文件时才会删除或改名其中的文件。建议：接受，前提是只绑 `127.0.0.1`（Vantage 的默认值）。
8. **怎么依赖一个小众、改动频繁的上游**：Vantage 14★，几乎每天都有提交，上游没有声明在 WSL 上测试过。建议：固定使用 v0.7.1，由用户手动决定何时升级，每次升级前用 `wsl-probe.sh vantage` 回归一遍。上游如果停更或出现无法接受的改动，再回到"自己做"。

**用户回答**：

5. 跟随模式不是硬要求，先用"Recent"列表手动代替。
6. 验收标准第 4 条改为"刷新后不跳回顶部，偏移约等于上方插入内容的高度"。
7. 接受写接口没有 CSRF 校验的风险。
8. 固定使用 v0.7.1。

**影响**：Vantage 原样满足放宽后的验收标准，路线收敛为 **A：原样使用 Vantage v0.7.1**。变化感知方式由 Vantage 决定（fsnotify 递归监听），不再单独讨论；ENOSPC 兜底暂不需要，真机上的上限是 524288。

### 第 3 轮（2026-09-28，待用户回答）

9. **本仓库原有的自研设计怎么处理**：`docs/architecture.md` 和 `AGENTS.md` 描述的是自研方案（Go + React 的 wsl-md-pulse）。选项：a. 保留为"自己做"的备选设计，在两份文档开头注明当前路线是 Vantage、这份设计暂不实施；b. 归档到 `docs/archive/`；c. 删除。建议：a。回到"自己做"的触发条件本来就写在路线里，保留设计的成本最低。
10. **怎么运行 Vantage**：选项：a. 需要时在一个 WSL 终端标签页里前台运行，关掉就停；b. 后台常驻（systemd 用户服务），同时调大 `.wslconfig` 的空闲超时，避免 WSL 自动停机。建议：a。关掉所有终端后服务能否存活还没实测；用法也是"跑 codex 时才看"，前台运行最简单可靠。
11. **怎么打开预览页**：Vantage 默认用 `xdg-open` 打开浏览器，WSL 里多半没有。选项：a. 加 `--no-open`，固定端口（默认 8000），在 Windows 浏览器里收藏 `http://127.0.0.1:8000/`；b. 等 `browser` 探测结果再定一个自动打开的命令。建议：a。URL 用 `127.0.0.1` 而不是 `localhost`，与真机结果一致。
12. **笔记根目录**：Vantage 一次只接一个根目录。建议：一个固定的 ext4 目录（例如 `~/notes`），codex 的输出都写在它下面。实际路径请告诉我。如果 codex 会写在多个项目目录里，需要另外讨论（多开几个端口，或者用一个公共的上级目录做根目录）。
