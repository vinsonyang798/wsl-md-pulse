# Spec：`mdv`：在 WSL 里一条命令打开 Markdown 预览页

术语见仓库根目录 `CONTEXT.md`（笔记根目录、写入方、预览页、当前文档、跟随模式、阅读位置）。路线决策见 `.scratch/wsl-md-sync-feasibility/issues/06-choose-route.md`，真机依据见同目录的 `05-real-machine-verification.md`。

## Problem Statement

用户在 WSL2 里用 codex cli 这类写入方生成和修改 Markdown 文档，文档分散在多个项目目录中，都在 ext4 上。用户想在 Windows 浏览器里边看边等 agent 改：文档一改，预览页就自动刷新，不用手动刷新，也不用每次去想端口、地址和怎么启动服务。

VS Code 内置预览经用户实测不会自动刷新，已经排除。现成工具 Vantage 满足放宽后的验收标准，但直接用它有三处不顺手：

- 要记住启动参数；
- 它自己打开浏览器时调用的 `xdg-open`，在 WSL 里不一定能打开 Windows 浏览器；
- 同时看多个目录时，端口要自己管。

## Solution

提供一条类似 `code .` 的命令 `mdv`。用户在 WSL 终端里进入想看的目录，输入 `mdv`：

1. Windows 浏览器随即打开这个目录的预览页，左侧是目录树，右侧是渲染后的文档；
2. 终端提示符立即返回，用户可以接着在同一个终端里运行 codex；
3. 写入方修改文档后，预览页自动刷新。

每个目录各对应一个独立的 Vantage 实例，这个目录就是它的笔记根目录。端口由 Vantage 自动分配，从 8000 开始，被占用就往后找。在同一个目录再次运行 `mdv`，只重新打开浏览器，不会重复启动。关闭启动 `mdv` 的终端标签页后，它启动的实例随之停止。另外提供列出、停止、安装 Vantage 的子命令。

Vantage 固定使用 v0.7.1，不做任何修改。`mdv` 只负责启动、复用、打开浏览器和随终端退出，不负责渲染、监听文件，也不经手任何 HTTP 或 WebSocket 通信。

## User Stories

1. 作为在 WSL 里工作的用户，我想在任意目录输入 `mdv` 就打开该目录的预览页，这样不用记 Vantage 的启动参数。
2. 作为用户，我想用 `mdv <目录>` 预览一个不是当前目录的目录，这样不用先 `cd` 过去。
3. 作为用户，我想让 `mdv` 自动打开 Windows 默认浏览器，这样不用复制 URL。
4. 作为用户，我想在运行 `mdv` 后立即拿回终端提示符，这样可以在同一个终端里接着运行 codex。
5. 作为用户，我想在终端里看到预览页的 URL，这样浏览器没打开或被我关掉时，还能手动打开。
6. 作为用户，我想让 `mdv` 自动选一个空闲端口，这样永远不用考虑端口。
7. 作为同时处理多个项目的用户，我想在第二个、第三个目录里运行 `mdv` 时自动得到各自的端口，这样几个预览页可以同时开着、互不干扰。
8. 作为用户，我想在同一个目录里重复运行 `mdv` 时只重新打开浏览器，而不是再起一个实例，这样不会出现同一个目录占好几个端口的情况。
9. 作为用户，我想在关掉浏览器标签页后，再次运行 `mdv` 就能回到同一个地址，这样可以随时找回预览页。
10. 作为用户，我想让我关闭终端标签页后，从这个标签页启动的预览随之停止，这样不会留下没人管的后台进程。
11. 作为用户，我想用 `mdv list` 查看正在运行的预览及其 URL 和目录，这样知道自己开了哪些。
12. 作为用户，我想用 `mdv stop` 停止当前目录的预览，这样不用关终端就能释放它。
13. 作为用户，我想用 `mdv stop <目录>` 停止指定目录的预览。
14. 作为用户，我想用 `mdv stop --all` 一次停止全部预览。
15. 作为用户，我想在 `mdv stop` 返回时实例已经真正退出，这样紧接着再运行 `mdv` 能拿回原来的端口。
16. 作为第一次使用的用户，我想用 `mdv install-vantage` 一条命令装好固定版本的 Vantage，这样不用自己去 GitHub 找发布包。
17. 作为在意供应链安全的用户，我想让安装过程校验发布包的 sha256，校验失败就中止，这样不会装上被篡改的二进制。
18. 作为 ARM64 设备上的用户，我想让安装命令自动选对架构的发布包。
19. 作为已经用探测脚本下载过 Vantage 的用户，我想让 `mdv` 直接复用那份二进制，这样不用重复下载。
20. 作为想用别的 Vantage 二进制的用户，我想通过环境变量指定它的路径，这样可以临时换版本做对比。
21. 作为没装 Vantage 的用户，我想在运行 `mdv` 时看到明确提示，告诉我先运行 `mdv install-vantage`。
22. 作为用户，我想在 Vantage 启动失败时看到它自己的输出，这样知道失败的原因，比如配置文件里写了一个被占用的端口。
23. 作为用户，我想在目录不存在或不是目录时得到清楚的报错，退出码非零。
24. 作为不小心在 `/mnt/c` 下运行 `mdv` 的用户，我想得到"该目录在 Windows 盘上、改动可能不会刷新"的警告，这样知道预览不刷新的原因。
25. 作为环境里恰好设置了 `PORT` 变量的用户，我想让 `mdv` 不受它影响，仍然自动选端口。
26. 作为 `cmd.exe` 调用失败的用户，我想让 `mdv` 自动改用 `powershell.exe` 打开浏览器。
27. 作为 Windows 互操作被禁用、或两种方式都失败的用户，我想让 `mdv` 只打印 URL 并提示手动打开，而且不当作启动失败。
28. 作为用户，我想在 WSL 当前目录是 Linux 路径时，打开浏览器也不出现"不支持 UNC 路径"的警告。
29. 作为用户，我想用 `mdv --help` 查看用法和安装方法。
30. 作为用户，我想让预览只能从本机访问，也就是只绑 `127.0.0.1`，这样局域网里的其他人看不到我的文档。
31. 作为多用户机器上的用户，我想让 `mdv` 的运行状态只有我自己能读写，这样别人无法冒充或篡改我的预览记录。
32. 作为用户，我想在写入方修改笔记根目录下任何一篇文档（包括新建的子目录里的文档）后，预览页自动更新当前文档和目录树。
33. 作为用户，我想在刷新后不跳回页面顶部，这样不会丢失大致的阅读进度（偏移约等于上方新插入内容的高度，可以接受）。
34. 作为用户，我想在预览页里看到 GFM 表格、任务列表、代码高亮、Mermaid 图、本地图片，并能点击文档间的相对链接。
35. 作为想知道 agent 刚改了哪篇的用户，我想借助预览页侧栏里按修改时间排序的"Recent"列表手动切换，以此代替跟随模式。
36. 作为以后可能升级 Vantage 的维护者，我想让版本号和校验和集中在一处定义，这样升级只需改一处，再用真机探测脚本回归一遍。
37. 作为将来决定改为自研的维护者，我想让 `mdv` 的命令行用法不依赖 Vantage 特有的概念，这样换掉底层实现时，用户的使用习惯不用变。

## Implementation Decisions

- **形态**：一个独立的 bash 脚本，安装到用户的 `~/.local/bin/`。只依赖 bash、coreutils 和 curl，其中 curl 只在安装 Vantage 时使用。WSL 侧满足零运行时依赖，Windows 侧不装任何东西。
- **命令行接口**：
  - `mdv [目录]`：启动或复用该目录的预览，默认是当前目录。
  - `mdv list`：每行输出 `URL<TAB>目录`；没有预览时输出一句提示。
  - `mdv stop [目录|--all]`：停止指定目录或全部预览，等实例退出后再返回；最多等约 5 秒。
  - `mdv install-vantage`：安装固定版本的 Vantage。
  - `mdv -h|--help`：显示用法。
  - 出错时向 stderr 输出以 `mdv:` 开头的信息，退出码为 1。
- **一个目录一个实例**：
  - 目录先取绝对规范路径（解析符号链接），同一个目录的不同写法视为同一个预览。
  - 每个实例运行 `vantage serve <目录> --no-open`，不用 daemon 模式，因为 daemon 模式需要事先把目录写进配置，与"进哪个目录就看哪个"不符。
- **端口**：
  - `mdv` 不传端口，让 Vantage 从 8000 开始自动往后找空闲端口。
  - 启动 Vantage 时去掉环境变量 `PORT`，因为 Vantage 把它当作显式端口，显式端口被占用时会直接启动失败。
  - 实际地址从 Vantage 启动输出里的 `Serving on http://<host>:<port>` 读取，等待上限约 15 秒。超时或进程提前退出，都按启动失败处理：结束进程，把 Vantage 的输出转给用户，并清除状态记录。
- **运行状态**：
  - 放在每个用户私有的运行时目录里：优先用 `XDG_RUNTIME_DIR`，没有就退到 `/tmp` 下按 uid 区分的子目录。目录权限为 700。
  - 每个预览按目录路径的哈希存四项：进程号、URL、目录、Vantage 的日志。
  - 进程号不存在的记录视为已失效，在复用、`list`、`stop` 时顺手清掉。
- **随终端退出**：
  - Vantage 在后台运行，标准输入接 `/dev/null`，输出写进日志，与终端脱开。
  - 另起一个看护进程：它忽略 SIGHUP，每约 2 秒检查一次运行 `mdv` 的那个 shell（父进程）是否还在；shell 不在了，就结束 Vantage。
  - 不依赖终端关闭时发出的 SIGHUP，因为 `mdv` 退出后，后台进程不在该终端的前台进程组里，收不到这个信号。
  - 同一个目录被别的终端复用时，实例仍归最初启动它的终端。
- **打开浏览器**：按以下顺序降级，前一种失败才试下一种。
  1. `cmd.exe /c start "" <url>`。优先从 PATH 找，找不到就用 `/mnt/c/Windows/System32/cmd.exe`。在 `/mnt/c` 目录下执行，避开 UNC 当前目录的警告。这是真机验证过的方式。
  2. `powershell.exe -NoProfile -NonInteractive -Command "Start-Process '<url>'"`。
  3. 只打印 URL，并提示手动打开。退出码仍为 0。

  URL 始终写成 `127.0.0.1`，不写 `localhost`。URL 里不含 `&`，不涉及 cmd 的转义问题。环境变量 `MDV_NO_BROWSER` 非空时跳过打开浏览器，只打印 URL，供测试和无界面环境使用。
- **Vantage 二进制的查找顺序**：
  1. 环境变量 `MDV_VANTAGE`；
  2. PATH 里的 `vantage`；
  3. `~/.local/bin/vantage`；
  4. 探测脚本下载的位置 `~/wsl-md-probe/bin/vantage`。

  都没有就提示运行 `mdv install-vantage`。
- **安装**：
  - 版本固定为 v0.7.1，按 `uname -m` 选 amd64 或 arm64。
  - 从 GitHub Release 下载 `vantage_0.7.1_linux_<arch>.tar.gz`，用内置的 sha256 校验（Release 本身没有提供校验和文件，校验值由 agent 下载后计算并写死）。
    - amd64：`d96363830216fa6a27abe4fc2f81150aeac42d8b2cbc4790806b77c3f78f89a8`
    - arm64：`7dd5c2173e5c310a20e2bd61069c3689d99b2a8eaa64f28d3e353496b65abb9f`
  - 只解压其中的 `vantage`，装到 `~/.local/bin/`，临时文件用完即删。
  - 如果 `~/.local/bin` 不在 PATH 里，给出提示。
  - 版本号和校验和集中在脚本顶部定义。
- **`/mnt/` 警告**：目录位于 `/mnt/` 下时，只警告、不阻止。当前验收标准只覆盖 ext4。
- **安全**：
  - 沿用 Vantage 的默认值：只绑 `127.0.0.1`，WebSocket 校验 Origin，路径做 `EvalSymlinks` 根目录校验。
  - `mdv` 不传 `--host`，也不提供改绑地址的选项。
  - 用户已接受 Vantage 写接口没有 CSRF 校验的风险。
- **与自研备选的关系**：`mdv` 这个命令名和它的命令行用法，是面向用户的稳定接口。将来转为自研时，底层换掉，接口保持不变。自研二进制保留 `mdview` 这个名字。

## Testing Decisions

- **只测外部行为**：把 `mdv` 当黑盒，通过命令行、退出码、stdout/stderr、它打开浏览器时发出的调用、端口上的 HTTP/WebSocket 响应和进程是否存在来判断。不测函数内部，也不去读状态文件的格式。
- **测试接缝（唯一一个）**：`mdv` 的命令行加上它读取的环境。
  - `MDV_VANTAGE` 或 PATH：注入真实的 Vantage v0.7.1。只有在需要制造启动失败时，才换成一个立刻退出的假程序。
  - PATH 里放假的 `cmd.exe` 和 `powershell.exe`：它们把收到的参数记进文件，并可以设成成功或失败，用来验证降级顺序和参数格式。
  - `MDV_NO_BROWSER`：跳过打开浏览器。
  - `XDG_RUNTIME_DIR` 和 `HOME`：把运行状态和安装位置隔离到临时目录。
  - "所属终端"：在 tmux 会话（或其他伪终端）里运行 `mdv`，再关闭会话，以此模拟关闭终端标签页。
- **要覆盖的行为**：
  - 首次启动时得到 `http://127.0.0.1:8000/`；
  - 同一个目录复用同一个实例，并再次打开浏览器；
  - 第二个目录得到 8001；
  - 设置了 `PORT` 不影响自动选端口；
  - 浏览器调用的参数是 `/c start "" <url>`；
  - `cmd.exe` 失败时改用 powershell，都失败时只提示、退出码仍为 0；
  - `list`、`stop`、`stop <目录>`、`stop --all` 的输出，以及 `stop` 返回时进程已退出；
  - 关闭所属终端后几秒内实例退出；
  - 目录不存在、找不到 Vantage、Vantage 启动失败时的报错和退出码；
  - `/mnt/` 警告；
  - 安装后 `vantage --version` 输出 0.7.1，校验和不符时中止；
  - 通过 `mdv` 启动的实例，在文件被修改后约 100ms 推送 `files_changed`。
- **已有的做法可参考**：
  - 本仓库没有 shell 脚本的自动化测试框架，Go/前端的测试约定针对的是暂不实施的自研代码，不适用。
  - 可参考的是这次实现时的手工回归：用 tmux 驱动交互式 shell，配合假 `cmd.exe` 和真实的 Vantage，记录见 PR 附带的 `mdv-test.log`。
  - 另一份可参考的是 `.scratch/wsl-md-sync-feasibility/probe/wsl-probe.sh` 里用标准库写的 WebSocket 客户端。
  - 如果要落成自动化测试，建议写一个纯 bash 的测试脚本，只依赖 tmux、curl 和 python3 标准库，放在 `mdv` 旁边。
- **真机验收**：云端没有 Windows。浏览器是否真的打开，需要用户在自己的 WSL 上运行一次 `mdv` 确认。`cmd.exe /c start` 这种方式本身已经在真机上验证过。

## Out of Scope

- 修改 Vantage：跟随模式、按标题段落恢复阅读位置、刷新时不白屏、严格只读、给写接口加 CSRF 校验，都不做。
- 自研预览服务（`docs/architecture.md` 里的 Go + React 设计）。
- daemon 模式、开机自启、systemd 服务，以及关闭终端后仍保持运行。
- `/mnt/c` 等 Windows 盘上的目录：只警告，不保证刷新。
- 睡眠、断网、WSL 空闲关机后的恢复，大目录的性能，VPN 的影响：用户决定不再关注。
- 自动升级 Vantage，或检查是否有新版本。
- 在 Windows 侧安装任何东西。

## Further Notes

- 这份 spec 描述的行为已经有一版实现，与本 spec 一致，在路线决策的 PR 中提交。后续 agent 以本 spec 为准做维护、补自动化测试或重写。
- 升级 Vantage 的流程：
  1. 更新版本号和两个架构的 sha256；
  2. 用 `wsl-probe.sh vantage` 在真机上回归推送延迟和阅读位置；
  3. 确认启动输出里仍有 `Serving on http://...` 这一行，并且默认端口仍会自动往后找。`mdv` 依赖这两点。
- 已知限制：
  - 看护进程每约 2 秒检查一次，所以关闭终端后实例最多约 2 秒才退出，另加 Vantage 自己的退出时间。
  - 用户自己的 Vantage 配置里如果写死了端口，就会失去自动选端口的能力，这时 `mdv` 会把 Vantage 的报错原样转给用户。
